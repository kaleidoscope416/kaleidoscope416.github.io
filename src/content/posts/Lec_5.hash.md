### 1. 搜索 (Searching)

#### 概念与目标
* **记录形式：** 数据集合 $L$ 包含 $n$ 条记录，形式为 $(k_j, I_j)$，其中 $k_j$ 是键 (key)，$I_j$ 是与键关联的信息 。
* **搜索问题：** 给定一个特定的键值 $K$，目标是找到 $L$ 中键 $k_j = K$ 的记录（如果存在） 。
* **搜索类型：**
    * **成功搜索：** 找到了键 $k_j = K$ 的记录 。
    * **不成功搜索：** 没有找到键 $k_j = K$ 的记录 。
    * **精确匹配查询 (Exact-match query)：** 搜索键值精确匹配给定键值的记录 。
    * **范围查询 (Range query)：** 搜索键值落在给定范围内的所有记录 。

#### 搜索方法的分类
根据数据存储位置和访问方式，搜索方法可分为三类:
* **顺序和列表方法 (Sequential and list methods):** 适用于存储在 **RAM** 中的数据搜索 。
* **通过键值直接访问（哈希）(Direct access by key value (hashing)):** 适用于存储在 **RAM 或磁盘** 上的数据搜索 。
* **树型索引方法 (Tree indexing methods):** 主要用于搜索存储在 **磁盘** 上的数据 。

#### 搜索未排序数组（顺序搜索）
* **最坏情况时间复杂度：** $\Theta(n)$ 。
* **平均成本 $T_n$ 的计算：**
    * $p_i$ 是 $K$ 位于位置 $i$ 的概率 。
    * $p_n$ 是 $K$ 不在 $L$ 中的概率 。
    * $K$ 在位置 $i$ 需要 $i+1$ 次比较 ；$K$ 不在 $L$ 需要 $n$ 次比较 。
    * 平均成本公式：$$T_n = n p_n + \sum_{i=0}^{n-1} (i+1) p_i$$ 
    * 如果所有 $p_i$ 相等（$n \cdot p + p_n = 1$），则 $T_n$ 介于 $\frac{n+1}{2}$ 和 $n$ 之间 。

#### 搜索已排序数组
* 通过一次比较可以排除掉一段元素 。
* **跳跃搜索 (Jump search):**
    * 以步长 $j$ 检查元素（$L[j], L[2j], \dots$），直到 $L[mj] < K < L[(m+1)j]$ 。
    * 然后在 $(\text{L}[mj], \text{L}[(m+1)j])$ 范围内搜索剩余的 $j-1$ 个元素 。
    * 总成本（比较次数）$T(n, j) = m + j - 1 = \lfloor n/j \rfloor + j – 1$ 。当 $j = \sqrt{n}$ 时，T(n, j) 最小 。
* **二分搜索 (Binary Search):** 基于“分治”原则 。
    * 如果对键值分布一无所知，二分搜索是最佳选择 。
    * 如果键值分布已知，可以使用“计算”二分搜索（如查字典）。

#### 自组织列表 (Self-Organizing Lists)
* 按记录的预期访问频率而非键值排序 。
* 将最常请求的记录放在列表的最前面，顺序搜索从第一位开始 。
* 当无法事先知道访问频率或频率会随时间变化时，使用启发式策略重新排序列表 。
    * **计数 (Count):** 存储每次访问次数，始终按此顺序维护记录 。
    * **移到前部 (Move-to-front):** 找到记录后将其移到列表的最前端 。
    * **转置 (Transpose):** 找到记录后将其与其在列表中紧邻的前一个记录交换位置 。

### 2. 哈希 (Hashing)

#### 需求与优势
* 传统数据结构（如树）依赖比较操作，查找和插入通常需要 $O(\log N)$ 时间 。
* **哈希表 (Hash tables)** 是一种抽象数据类型，旨在实现 $O(1)$ 的查找 (Find) 和插入 (Insert) 操作 。
* 哈希表仅支持有限的操作集合：**Insert**、**Find** 和 **Delete**，不暗示元素的顺序 。

#### 直接寻址表 (Direct Address Tables)
* **假设：** 键是集合 $U=\{0, 1, \dots, m-1\}$ 中的整数，$m$ 较小，且没有两个元素具有相同的键 。
* **实现：** 直接将元素存储在数组位置 $\text{array}[\text{key}]$ 。
* **操作：** 查找、插入和删除都非常简单 。
    * $\text{Find}(T, k)$ 返回 $T[k]$ 。
    * $\text{Insert}(T, x)$ 设置 $T[\text{key}[x]] = x$ 。
    * $\text{Delete}(T, x)$ 设置 $T[\text{key}[x]] = \text{NULL}$ 。
* **问题：** 如果最大的可能键 $m$ 远大于实际存储的元素数量 $|K|$（即 $|U| \gg |K|$），则表非常稀疏，浪费空间，甚至可能太大而无法放入内存 。

#### 哈希方案 (Hashing Schemes)
* **目的：** 将较大的键集合 $U$ 映射到一个接近实际元素数量 $|K|$ 的较小集合 。
* **哈希函数 (Hash function):** 计算从键 $K$ 到表索引的方法（从 $U$ 映射到索引） 。
* **要求：**
    * 输出值必须小于数组大小 。
    * 应该尽可能均匀地分布 。
    * 哈希值应取决于整个键的所有值及其位置 。

#### 键与哈希函数
* **简单哈希（针对均匀分布的实数）：** 如果 $0 \le s < 1$ 均匀分布，则 $\text{hash}(s) = \lfloor s \cdot m \rfloor$ 是一个快速且好的哈希函数（$m$ 是表大小） 。
* **完美哈希 (Perfect Hashing):** 在某些情况下，可以将一个**已知**的键集唯一地映射到一组索引值（需要事先知道所有键） 。
* **模哈希函数 (Mod Hash Function):**
    * 使用模运算：$a \pmod{\text{size}}$ 。
    * 针对整数键：$\text{Hash}(\text{key}) = \text{key} \pmod{\text{TableSize}}$ 。
    * **注意：** 必须仔细选择 $\text{TableSize}$，通常选择**素数** 。
* **中平方方法 (Mid-square method):** 将键值平方，然后取结果的中间 $r$ 位作为哈希值 。
* **非数值键 (Nonnumerical Keys):**
    * 需要先将键（如字符串）转换为自然数 。通常使用 **ASCII 字符编码** 。
    * 简单相加：$\sum c_i$。问题在于短字符串不能均匀哈希到整个表，且不同字符组合可能哈希到相同值（如“abc”, “bca”, “cab”） 。
    * **Horner's Rule (秦九韶算法):** 将字符串 $c_1 c_2 \dots c_n$ 视为基数 256 的数字 $256^{n-1}c_1 + 256^{n-2}c_2 + \dots + c_n$，使用递推公式计算哈希值:
        $$r := (c[i] + 256 \cdot r) \pmod{\text{TableSize}}$$

### 3. 冲突解决 (Collision Resolution)

当两个不同的键哈希到相同的值时，发生冲突 (Collision) 。

#### 分离链接法 (Separate Chaining)
* **方法：** 哈希表的每个单元格存储一个指向链表的指针，该链表包含所有哈希到该槽位的记录 。
* **查找：** 计算哈希值，然后在对应的链表上执行查找 。
* **链表选择：** 通常使用链表（查找时间 $O(N)$），但如果链很长，也可以考虑使用二叉搜索树（查找时间 $O(\log N)$） 。

#### 负载系数 ($\lambda$)
* **定义：** $\lambda = N / \text{TableSize}$ （$N$ 是存储的项数） 。
* **平均链表长度：** $\lambda$ 。
* **平均访问时间：** $O(1) + O(\lambda)$ 。
* **目标：** $\lambda$ 应小于 1 但接近 1，如果使用链接法，$\lambda > 1$ 也能工作 。

#### 开放寻址法（探测法）(Open Addressing / Probing)
* **方法：** 表中不使用链接，所有键都存储在表内 。
* **冲突处理：** 当一个记录的“主位置”被占用时，冲突解决方法会搜索一个槽位序列，并尝试找到一个空闲槽位 。
* **查找：** 检查 $h_0(X), h_1(X), h_2(X), \dots$ 直到找到 $X$ 或找到一个空位置 。
* **探测序列：** $h_i(X) = (\text{Hash}(X) + p(X, i)) \pmod{\text{TableSize}}$，其中 $p$ 是冲突解决函数 。
* **主要变体：**
    * **线性探测 (Linear Probing):** $p(X, i) = i$ 。
        * **问题：** 导致**主聚集 (Primary clustering)**，即形成连续的占用位置块，使得后续的冲突记录更有可能落入这个块中，导致聚集块越来越大 。
        * 可通过使用 $p(K, i) = c \cdot i$ 改进，其中 $c$ 应与 $M$ **互质**，以确保探测序列遍历所有槽位 。
    * **伪随机探测 (Pseudo-random probing):** $p(K, i) = \text{Perm}[i-1]$，所有操作使用相同的随机排列 。
    * **二次探测 (Quadratic Probing):** $p(X, i) = i^2$ 或 $p(K, i) = c_1 i^2 + c_2 i + c_3$ 。
        * 可以消除主聚集 。
        * **注意：** 如果使用二次探测且表大小为素数，当表至少有一半为空时，总能插入新元素 。
        * **问题：** 可能出现**二次聚集 (Secondary clustering)**，即哈希到同一主位置的键总是遵循相同的探测序列 。
    * **双重哈希 (Double Hashing):** $p(K, i) = i \cdot \text{Hash}_2(K)$ 。
        * 探测序列为 $h_1(X), h_1(X) + h_2(X), h_1(X) + 2 \cdot h_2(X), \dots \pmod{\text{TableSize}}$ 。
        * 必须保证 $\text{Hash}_2(X)$ **不为 0 且不为 $M$ 的约数** 。

#### 重新哈希 (Rehashing)
* **需求：** 当表太满（$\lambda \approx 1$）或发生太多删除操作时，运行时间会变长，插入可能会失败 。
    * **惰性删除 (Lazy deletion)** 意味着删除操作并不会减少表的满度 。
* **方法：**
    1.  建立一个大小约为原表**两倍**的新哈希表 。
    2.  遍历旧表，忽略已删除的项 。
    3.  为每个未删除的键重新计算哈希值，并将其放入新表中的新位置 。
* **成本：** $O(N)$，但发生频率很低 。
* **策略：** **“中庸之道”**是最佳选择，即当表达到某个特定的负载系数时进行重新哈希 。

#### 开放寻址分析
* **空表时：** 插入、删除和查找通常只需要一次记录访问 。
* **表变满时：** 预期成本是负载系数 $\lambda$ 的函数 $f(\lambda)$ 。
* **经验法则：** 设计哈希系统时，应确保哈希表永远**不要超过一半满** 。

### 4. 练习与提示
* **练习 1 (线性探测):** 7 槽哈希表，使用 $h(k) = k \pmod 7$ 和线性探测 。

    * 哈希函数经常是性能缺陷的原因 。
    * 哈希函数通常会使代码不可移植 。
    * 如果某个哈希函数在你的数据上表现不佳，请更换一个 。
